# پاسخ احوال‌پرسی و رفع تکرار فرم بدون نتیجه

**گزارش کاربر:** واردکردن «چطوری» در چت دستیار خرید، به‌جای پاسخ کوتاه، مسیر جست‌وجوی محصول را آغاز می‌کرد و عبارت بدون کالای مطابق، سه پیام «با این شرایط گزینه منطبقی پیدا نشد» تولید می‌کرد.

## تشخیص
- `isGreetingOnly()` در React فقط «سلام چطوری» را پوشش می‌داد، نه «چطوری» به‌تنهایی.
- `render_results_node()` در بک‌اند برای جست‌وجوی بی‌نتیجه به‌درستی `empty_state` و فرم قابل اصلاح صادر می‌کرد؛ اما رندرر هم متن `assistant.message` و هم عنوان `empty_state` و هم `SchemaForm` با همان عنوان را نشان می‌داد.
- پیام احوال‌پرسی و سؤال‌های دقیق درباره **راهنمای استفاده از همین دستیار** نیازی به فراخوانی BoxAPI، جست‌وجوی دیتابیس یا ایجاد مأموریت جدید ندارند.

## اصلاح
- نگاشت بسته و محدود برای «چطوری»، «خوبی» و احوال‌پرسی‌های ساده؛ درخواست خرید مثل «چطوری یه لپ‌تاپ مناسب انتخاب کنم» همچنان وارد جست‌وجوی محصول می‌شود.
- راهنمای کوتاه استفاده برای «راهنما»، «چطور ازت استفاده کنم» و جمله‌های هم‌معنیِ مشخص، بدون مصرف اعتبار API.
- در حالت `empty_state` متن تکراری پیام از دید حذف می‌شود؛ عنوان داخلی فرم نیز حذف می‌شود، ولی فیلدها، شرایط سخت، توضیح اصلی و اقدام «جست‌وجوی دوباره» حفظ می‌شوند.
- تست‌های واحد مربوط به تشخیص مکالمه و کنترل UI؛ سناریوی Playwright برای «چطوری»، «راهنما» و عدم تکرار فرم.

**محدودیت:** این مسیر احوال‌پرسی/راهنما در اپ React به‌صورت محلی پاسخ می‌دهد و مثل سایر احوال‌پرسی‌های موجود در mission backend persist نمی‌شود. برای درخواست API مستقیم بک‌اند، routing مکالمه هنوز بخشی از پروژه آینده است.

## وضعیت
یک شاخه و یک PR متمرکز، با یک اجرای CI در زمان ready. فایل‌ها و migration دیتاست تغییری نکرده‌اند.
