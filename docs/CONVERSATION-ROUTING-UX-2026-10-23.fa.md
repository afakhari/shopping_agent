# Root-cause fix: «احوال شما؟» در دستیار خرید، نه جست‌وجوی کالا

## گزارش
کاربر در نسخه محلی «احوال شما؟» را فرستاد و به‌جای پاسخ کوتاه، ۱۲۰ کالای نامرتبط، از جمله لوازم آرایش و تیغ جراحی، دریافت کرد. در تصویر محدودیت «خرید اعتباری حضوری» هم فعال بود؛ این شرط نباید خودکار تغییر کند.

## چرا رخ داد
1. تشخیص زبانی UI مبتنی بر تطبیق دقیق عبارت‌ها بود؛ «چطوری» را می‌شناخت اما «احوال شما؟» را نه.
2. بک‌اند API همان guard را نداشت و استخراج نیت از هر عبارت غیرخالی می‌توانست فراخوانی BoxAPI انجام دهد.
3. جست‌وجوی کاتالوگ برای تطبیق توکن‌ها `OR` دارد و واژه‌های عمومی اگر به جست‌وجو برسند نتایج نامرتبط می‌سازند.

## حل چندلایه
- UI: تشخیص full-string احوال‌پرسی رایج و حالت‌های عربی/فارسی/اعراب؛ بدون فراخوانی مدل یا جست‌وجو.
- Backend: guard مستقل برای API direct/clients آینده؛ پیام‌های اجتماعی به پاسخ کوتاه و سه رویداد persist شده تبدیل می‌شوند؛ هیچ catalog/LLM فراخوانی و هیچ تغییری در hard filters، state، محصولات منتخب یا مأموریت قبلی رخ نمی‌دهد.
- Graph: `_query_from_message` برای گفت‌وگوی اجتماعی خالی است و بدون محصول کاتالوگ فراخوانی نمی‌شود.
- SSE: پاسخ محاوره‌ای با `assistant.message` و `turn.completed.intent_parser=local_conversation` کامل محسوب می‌شود؛ برای آن کامپوننت کالا یا فرم ساختگی نمی‌سازیم. شرط terminal marker برای پاسخ‌های خرید همچنان برقرار است.
- Regression: تست‌های PHP نداریم؛ این مسیر با Django SimpleTestCase + APIClient، Vitest و Chromium در عرض موبایل بررسی می‌شود؛ جمله‌هایی مانند «سلام هدفون می‌خواهم» نباید به اشتباه smalltalk تلقی شوند.

## مرزها
- تطبیق محافظه‌کارانه فقط برای عبارت‌های کامل؛ جمله دارای موضوع واقعی خرید همچنان به جست‌وجوی دیتابیس می‌رود.
- LLM هنوز در این نسخه عمدتاً برای استخراج نیت خرید استفاده می‌شود، نه پاسخ‌گویی عمومی یا ادعای قیمت زنده.
- پیام‌های اجتماعی محلی UI در مرورگر بدون هزینه پاسخ داده می‌شوند؛ پاسخ مستقیم API persist می‌شود.
- وضعیت داده، فروشگاه، بودجه و اعتبار ثبت‌شده دست‌نخورده باقی می‌ماند.
