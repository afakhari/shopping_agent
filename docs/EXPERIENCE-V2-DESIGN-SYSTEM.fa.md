# Bazaar Compass Experience v2 | دیزاین سیستم فارسی و راهنمای بازطراحی

## مبنای تصمیم

پروژه اکنون React 19، Vite، Tailwind CSS 4، آیکون‌های Lucide، SSE و کامپوننت‌های چندشکلی GenUI دارد. مهاجرت یک‌باره همه اجزا به shadcn/ui ریسک regression بالایی برای مأموریت خرید ایجاد می‌کرد. **راهکار انتخابی:** قرارداد دیداری و معنایی مستقل، توکن‌های قابل‌استفاده مجدد و حفظ کنترل‌های عملیاتی موجود؛ **shadcn/ui نصب نشده است**.

گزینه‌های بررسی‌شده:
- [shadcn/ui RTL](https://ui.shadcn.com/docs/rtl): پشتیبانی رسمی از کلاس‌های منطقی و DirectionProvider. انتخاب نخست برای Dialog، Sheet، Tabs و Comboboxهای جدید در اسپرینت بعد.
- [Radix Primitives](https://www.radix-ui.com/primitives/docs/utilities/direction-provider): کنترل کیبورد/فوکوس/جهت با اجزای بدون استایل و پشتیبانی از RTL.
- [React Aria](https://react-aria.adobe.com/quality): بین‌المللی‌سازی و دسترس‌پذیری قوی، با هزینه یکپارچه‌سازی بالاتر در codebase فعلی.
- کامپوننت‌های موجود: امکان تغییر تدریجی با حفظ API و رفتار واقعی، بدون dependency اضافه.

## هویت بصری

- **شخصیت:** قابل اعتماد، ایرانی، گرم، سبک و داده‌محور. از ظاهر فروشگاهی شلوغ یا چت‌باکس بی‌هویت پرهیز شده است.
- **برند:** یشمی `#145c46`، کاغذ شیری `#f7f7f2`، سفید، موفقیت ملایم `#e9f5ee`، کهربایی برای هشدار ثانویه.
- **تایپوگرافی:** Vazirmatn با fallback به Tahoma/Segoe UI؛ اعداد و مبلغ‌ها با formatting فارسی موجود. در UI فارسی letter-spacing فشرده اعمال نمی‌شود.
- **کامپوننت‌ها:** گوشه‌های ۱۰/۱۴/۲۲ پیکسل، تأکید واضح روی CTA اصلی، سایه نرم، حداقل هدف لمسی حدود ۴۴ پیکسل، مرزهای کم‌کنتراست ولی قابل رؤیت.
- **حالات:** focus-visible واضح، hover ملایم، disabled، درحال‌پردازش، خطا، بدون‌نتیجه و گسترش جزئیات. با reduced motion، انیمیشن غیرضروری حذف می‌شود.

## معماری نسخه جدید

`frontend/src/experience-v2.css` **آخرین stylesheet** پس از `styles.css`، `styles-polish.css`، `chat-shell.css`، `design-system.css` و فایل‌های نتیجه/برنامه مراجعه بارگذاری می‌شود. تمام بازنویسی‌ها زیر کلاس `.redesign-v2` قرار دارند تا حوزه اثر کنترل‌شده باشد. این لایه فعلاً جایگزین legacy styles نشده است؛ در گام consolidation می‌توان استایل‌های تاریخی تکراری را با تست تصویری حذف کرد.

`frontend/src/app/App.tsx` یک فضای کار دو ستونی برای دسکتاپ معرفی می‌کند: راهنمای چهار گام خرید در سمت راست، و گفتگوی واقعی در سمت چپ. مراحل راهنما **وضعیت پیشرفت ادعایی** نیستند و فقط نقشه راه UX را معرفی می‌کنند. در صفحه‌های کمتر از ۹۹۰ پیکسل، ستون راهنما به ردیف فشرده تبدیل می‌شود.

`MissionPanel.tsx` صفحه شروع با مثال‌های قابل اجرا، وضعیت صادقانه قیمت/موجودی، عنوان نتیجه و سلسله‌مراتب قیمت/فروشگاه دارد. SSE، فرم فیلتر، انتخاب موقعیت، مقایسه مدل، مقایسه فروشگاه و روند استعلام حذف یا دور زده نشده‌اند.

## قرارداد ریسپانسیو

| عرض | رفتار |
|---|---|
| بالاتر از ۱۱۵۰ px | راهنمای کامل چهار گام + صفحه کار گسترده، کارت‌های دو ستونی |
| ۹۹۱ تا ۱۱۵۰ px | راهنمای جمع‌وجور و کارت‌های انعطاف‌پذیر |
| ۷۲۱ تا ۹۹۰ px | حذف ستون ثابت، ردیف راهنمای خرید، صفحه کار تمام‌عرض |
| ۵۵۱ تا ۷۲۰ px | صفحه کار لبه‌به‌لبه با کادر پیام سازگار با لمس |
| ۳۸۶ تا ۵۵۰ px | کارت محصول تک‌ستونی، پیشنهادهای شروع تک‌ستونی |
| ۳۲۰ تا ۳۸۵ px | اکشن‌های کارت در دو خط برای حذف سرریز افقی |

اسکرول اصلی داخل گفتگو باقی می‌ماند؛ فضای `safe-area-inset-bottom` برای موبایل در نظر گرفته شده است. جهت صفحه `lang=fa, dir=rtl` است و از ویژگی‌های منطقی inline تا حد امکان استفاده شده است.

## صداقت اطلاعات

قیمت‌ها از داده واردشده می‌آیند؛ موجودی، تماس واقعی، ساعات بازبودن فعلی و ETA نباید بدون سند قطعی ارائه شوند. این دستور حتی برای طراحی کارت‌های چشم‌نواز نباید شکسته شود.

## روش پذیرش

۱. `npm run typecheck`، `npm run lint`، `npm test`، `npm run build` باید موفق باشند.
۲. مرورگر در عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۴۴۰ و ۱۹۲۰ پیکسل بررسی شود. بدون بریدگی متن، اسکرول افقی، افت فوکوس یا دکمه بی‌عمل.
۳. یک سناریو از شروع گفتگو تا جستجو، تغییر شرط، مقایسه، استعلام شبیه‌سازی‌شده، جایگزین و برنامه مراجعه اجرا شود.
۴. با کیبورد: Tab، Enter، Shift+Enter، Escape در دیالوگ‌های جدید، و ترتیب فوکوس RTL بررسی شود.
۵. تست در مرورگرهای Chromium و Firefox و روی موبایل واقعی، بعد از build کاربر، الزامی است.

**وضعیت فعلی:** بازطراحی UI در کد ثبت شده است؛ نمایش نهایی در مرورگر کاربر هنوز باید بازبینی بصری شود. این سند به‌معنی گذراندن تست بصری خودکار نیست.
