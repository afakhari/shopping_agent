# راهنمای مرحله پیش از انتشار و تحویل مسابقه | نسخه ۲۳ اکتبر ۲۰۲۶

**مرجع:** شرح چالش ترب: ویدئوی دمو حدود پنج دقیقه اجباری است و بدون آن اثر از داوری حذف می‌شود؛ انتشار روی سرور **۴۰ امتیاز** دارد. این فایل روش استقرار را توضیح می‌دهد، اما **وجود فایل به معنی استقرار واقعی نیست**.

## وضعیت و مرز گواهی
- PR قبلی #36 با CI پنج‌گانه موفق در `main` ادغام شد.
- بسته hardening شامل migrationهای 0007/0008، محدودیت تماس مدل و ورود HTTPS هنوز باید بر شاخه خود CI شود و سپس ادغام شود.
- هیچ دامنه/سرور، رمز، کلید BoxAPI یا اکانت Liara در پروژه ارائه نشده است. دسترسی عمومی، اتصال واقعی BoxAPI و فیلم هنوز تأیید نشده است.
- نقشه پیش‌فرض رایگان است: OSM اختیاری با کلیک، بدون کلید و بدون ادعای ETA واقعی.

## ترتیب پیش از انتشار
۱. آخرین SHA و پنج job تست خودکار GitHub را روی **همان SHA** بررسی کن؛ migrationها با `python manage.py migrate --check` و `makemigrations --check --dry-run` چک شوند.
۲. روی میزبان دارای فضای دیسک پایدار، `starcoach-dataset-v16-cap300-csv.zip` را از منبع مجاز و **خارج از Git** قرار بده؛ `verify_dataset --products 225903 --shops 6476 --offers 331506` باید موفق شود.
۳. `.env` خصوصی با `POSTGRES_PASSWORD` قوی، `DJANGO_SECRET_KEY` حداقل ۳۲ کاراکتری، `DJANGO_ALLOWED_HOSTS` و `DJANGO_CSRF_TRUSTED_ORIGINS=https://...` ایجاد کن. مقدار `LLM_DAILY_MAX_CALLS=0` یعنی فراخوانی پولی مدل کاملاً خاموش؛ تنها پس از تأیید اعتبار و رضایت صاحب حساب، عدد مثبت بده.
۴. پراکسی TLS روی همان میزبان بر اساس `deploy/Caddyfile.example` را تنظیم کن و **فقط پورت‌های ۸۰ و ۴۴۳** را عمومی کن. `compose.production.yaml` پورت داخلی HTTP را به `127.0.0.1:8080` محدود می‌کند.
۵. قبل از اجرا دستور زیر را روی **میزبان** بزن:
```sh
docker compose -f compose.yaml -f compose.production.yaml config --quiet
docker compose -f compose.yaml -f compose.production.yaml up -d --build
docker compose -f compose.yaml -f compose.production.yaml exec -T backend python manage.py migrate --noinput
docker compose -f compose.yaml -f compose.production.yaml exec -T backend python manage.py verify_dataset --products 225903 --shops 6476 --offers 331506
```
۶. بعد از فعال‌سازی HTTPS، از بیرون سرور اجرا کن:
```sh
python scripts/predeploy_smoke.py --base-url https://YOUR-DOMAIN.example --active
```
این smoke بدون تماس با BoxAPI، سلامت سرویس، catalog، بازیابی نشست، استقلال نشست بیگانه و تکرار امن ایجاد مأموریت را می‌آزماید. بررسی `--require-model-configured` فقط **پیکربندی** را تأیید می‌کند، نه تماس واقعی با مدل.
۷. تست مسیر کامل روی همان URL با داده اصلی و BoxAPI با **رضایت کاربر و سقف مصرف** اجرا شود: نیاز فارسی، دو مدل، فروشنده در محدوده، شکست `no_answer` (شبیه‌سازی)، جایگزین واجد شروط، برنامه مراجعه، refresh و recovery. قیمت snapshot یا شماره جعلی را واقعی معرفی نکن.
۸. در موبایل واقعی اندازه‌های ۳۲۰/۳۶۰/۳۹۰، کنتراست، دسترسی با صفحه‌کلید، قطع شبکه، XSS، cookie Secure، ریدایرکت HTTPS، و نبود نشت کلید کنترل شود.
۹. ۲۰ سناریوی خطا و ۱۲ مسیر مستقل E2E باید با خروجی واقعی هر تست و SHA ثبت شوند؛ CI fixture به‌تنهایی ۱۲/۱۲ مستقل محسوب نمی‌شود.
۱۰. ویدئوی حدود ۵ دقیقه از **همین نسخه منتشرشده** ضبط و در سامانه مسابقه ارسال شود.

## معیار توقف انتشار
- HTTPS عمومی یا health/readiness سالم نیست؛ loop اشتباه redirect بین Nginx و Django وجود دارد.
- داده اصلی وارد نشده، رکوردهای لازم کمتر از انتظار یا `verify_dataset` ناموفق است.
- کد untested، migrations انجام‌نشده، secret در Git یا مرورگر، هزینه مدل بدون سقف یا نام/شماره فروشگاه جعلی به‌عنوان واقعی معرفی شده است.
- خطای عبور از فیلتر بودجه/اعتبار/موقعیت یا دسترسی بین دو نشست رخ می‌دهد.
- روند مراجعه یا شکست فروشنده بدون توضیح **شبیه‌سازی** ارائه می‌شود.

## برگشت امن
مخزن را به SHA تأییدشده قبلی برگردان؛ **قبل از migration و به‌ویژه پیش از هر rollback از پایگاه داده snapshot بگیر**. برگشت image بدون درنظرگرفتن schema جدید DB امن نیست. کلیدهای خصوصی را در GitHub، خروجی لاگ یا ویدئو نشان نده.

## کارهایی که اتوماتیک اثبات نمی‌شوند
قضاوت انسانی ۵۰ پرس‌وجوی relevance و Recall@10/MRR@10 معتبر، مشاهده RTL در موبایل واقعی، هزینه/پاسخ واقعی BoxAPI، دسترسی HTTPS از خارج و ضبط و ارسال ویدئوی اجباری. تا ثبت شواهد، همه باز هستند.
