# بازبینی و بازطراحی رابط چت‌محور Bazaar Compass

تاریخ بازبینی: ۲۲ اکتبر ۲۰۲۶

## یافته‌های پژوهش محصول

### ChatGPT Shopping Research / Product Discovery

در توضیح رسمی OpenAI، خرید پیچیده به شکل گفتگویی توصیف شده است: کاربر نیاز را بیان می‌کند، دستیار برای رفع ابهام سؤال می‌پرسد، محصولات به‌صورت بصری در همان تجربه ظاهر می‌شوند و کاربر می‌تواند گزینه‌ها را حذف کند، مشابه بخواهد، شروط را اصلاح کند و چند محصول را کنار هم ببیند. این الگو برای بازارکامپس مناسب است، اما داده‌های فروشگاه ایرانی و محدودیت واقعی تازگی قیمت باید جداگانه و صریح ارائه شوند.

منابع رسمی:
- https://openai.com/index/chatgpt-shopping-research/
- https://openai.com/index/powering-product-discovery-in-chatgpt/
- https://help.openai.com/en/articles/12911370-using-shopping-research

### Claude Artifacts

راهنمای رسمی Claude توضیح می‌دهد که ابزار یا خروجی بصریِ خودبسنده می‌تواند کنار گفتگو قرار بگیرد و مستقل از متن گفتگو قابل تعامل باشد. الگوی اقتباس‌شده برای بازارکامپس این است که فرم و جدول/مقایسه در جریان پاسخ دستیار قابل تعامل باشند؛ اما در MVP نیازی به پنل دوم دائمی نیست، چون هدف اصلی خرید گفتگویی و استفاده از صفحهٔ نمایش به شکل فشرده است.

منبع رسمی:
- https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them

## مشکل نسخهٔ قبل

- دو فایل `styles.css` و `styles-polish.css` تعدادی از یک selectorها و قواعد responsive را با ترتیب و ارتفاع‌های متفاوت override می‌کردند؛ به همین دلیل ظاهر و ارتفاع نهایی سخت‌تر پیش‌بینی می‌شد.
- shell فقط `min-height` داشت، نه ارتفاع اجباری viewport همراه با محدودیت overflow روی `html/body/#root`. بعضی viewportهای کوتاه می‌توانستند اسکرول صفحه ایجاد کنند.
- اطلاعات شفافیت/روند بررسی زیر composer قرار داشت و می‌توانست ارتفاع غیرضروری به پایین صفحه اضافه کند.
- در صورت سرو شدن `index.html` قدیمی، مرورگر ممکن بود همچنان bundle قبلی CSS/JS را دریافت کند. CSS از قبل به `main.tsx` وارد می‌شد، بنابراین «CSS اصلاً import نشده» از روی سورس تأیید نمی‌شود؛ باید تفاوت نسخهٔ محلی و Docker/کش مرورگر را هم بررسی کرد.

## الگوی نهایی رابط

- پوستهٔ تمام‌قد و chat-first، بدون hero/صفحهٔ معرفی یا پنل کاتالوگ دائمی.
- header باریک؛ نام دستیار و وضعیت اتصال بدون منوی ناوبری مزاحم.
- یک transcript مستقل با scroll داخلی؛ کل صفحه ثابت می‌ماند.
- composer پایین صفحه ثابت می‌ماند، textarea با متن رشد می‌کند و در ارتفاع زیاد داخل خود اسکرول دارد.
- حالت شروع فشرده: خطاب کوتاه و چهار اقدام پیشنهادی، بدون hero بزرگ و متن تبلیغاتی.
- در پاسخ دستیار، فرم‌های GenUI، نتایج محصول، مقایسه، وضعیت تماس شبیه‌سازی‌شده و برنامهٔ مراجعه داخل همان جریان رندر می‌شوند.
- رویدادهای شفافیت به انتهای transcript منتقل شده‌اند؛ composer را به پایین نمی‌رانند.
- کارت نتایج روی دسکتاپ دو ستونه و روی صفحهٔ باریک تک‌ستونه است؛ در صورت طولانی شدن گفتگو فقط transcript اسکرول می‌شود.
- `index.html` در Nginx no-store است تا bundle قدیمی به شکل ناخواسته حفظ نشود؛ دارایی‌های هش‌شدهٔ `/assets/` immutable cache می‌شوند.

## قواعدی که نباید نقض شوند

1. هیچ‌گاه کل `body` را برای دیدن پیام‌های طولانی اسکرول‌پذیر نکن؛ transcript تنها ناحیهٔ اسکرول عمودی است.
2. composer و ارسال پیام همیشه در دسترس بمانند.
3. در viewportهای خیلی کوتاه، spacing و جزئیات ثانویه کم شوند، اما ورودی و عملیات اصلی حذف نشوند.
4. پیام‌های طولانی و جدول مقایسه می‌توانند داخل transcript/جدول خود اسکرول داشته باشند. جلوگیری از هر نوع اسکرول برای یک گفتگوی نامحدود از نظر UX و فنی شدنی نیست؛ هدف حذف اسکرول صفحه و نمایش بی‌دردسر اقدامات اصلی است.
5. قیمت دیتاست «قیمت ثبت‌شده» است؛ موجودی جاری تنها با نتیجهٔ استعلام مشخص می‌شود و استعلام فعلی دمو شبیه‌سازی‌شده است.

## تأیید عملی بعد از اعمال

در Windows PowerShell:

```powershell
cd D:\projs\bazaar-compass

docker compose build --no-cache frontend
docker compose up -d --force-recreate frontend

$html = (Invoke-WebRequest 'http://localhost:8080/' -UseBasicParsing).Content
$html
$cssPath = [regex]::Match($html, 'href="([^"]+\.css)"').Groups[1].Value
$cssPath
$css = (Invoke-WebRequest "http://localhost:8080$cssPath" -UseBasicParsing).Content
$css.Contains('--bc-chat-canvas')
```

آخرین دستور باید `True` برگرداند. اگر `$cssPath` خالی بود یا جواب CSS `404` شد، ابتدا خروجی `docker compose ps` و لاگ Nginx بررسی شود؛ در آن حالت احتمالاً تصویر/محتوای فرانت‌اند تازه سرو نمی‌شود.

موارد بررسی در مرورگر: صفحهٔ ۳۲۰×۷۰۰، ۳۹۰×۸۴۴، ۷۶۸×۸۰۰ و ۱۴۴۰×۹۰۰؛ شروع تازه؛ فرم تکمیل نیاز؛ نتایج خالی؛ ۲ تا ۳ محصول برای مقایسه؛ خطای API؛ و status شبیه‌سازی‌شدهٔ استعلام.
