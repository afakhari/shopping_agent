# بازبینی طراحی بصری و Design System بازارکامپس

**تاریخ بازبینی:** ۲۲ اکتبر ۲۰۲۶
**دامنه:** رنگ‌ها، فونت فارسی، وزن و مقیاس تایپ، کارت‌ها، فرم‌های Generative UI، وضعیت‌ها، composer، RTL و اندازه‌های تعاملی.

## جمع‌بندی تصمیم

جهت بصری انتخاب‌شده یک رابط **چت‌محور، مینیمال، روشن و عمل‌گرا** است؛ نه صفحهٔ لندینگ و نه داشبورد فروشگاهی. گفتگو باید نقطهٔ کانونی باقی بماند، در حالی‌ که نتایج و فرم‌های پویا درون جریان گفتگو نمایش داده می‌شوند.

به‌جای تقلید سطحی از رنگ‌بندی یک محصول، از اصول مشترک طراحی سیستم‌های بالغ استفاده شده است: رنگ‌های معنایی بر پایهٔ نقش، مقیاس تایپوگرافی محدود، ارتفاع کنترل‌های قابل لمس، مرزبندی سبک، یک CTA اصلی در هر کارت و کارت‌های درون گفتگو فقط زمانی که تعامل بصری واقعاً ارزش دارد.

## یافته‌های بررسی

### ۱. معماری CSS

قبل از این تغییر سه فایل `styles.css`، `styles-polish.css` و `chat-shell.css` به‌ترتیب در `main.tsx` وارد می‌شدند. این فایل‌ها به‌تدریج selectorهای هم‌نام و مقدارهای متفاوتی برای رنگ، فاصله، اندازهٔ متن و شعاع گوشه‌ها پیدا کرده‌اند. به همین دلیل، یک عنصر ممکن بود رنگ و وزن یکسانی را از چند جای مختلف دریافت کند.

**تصمیم:** فایل `design-system.css` به‌عنوان آخرین لایهٔ استایل اضافه شد. متغیرهای ریشه منبع اصلی رنگ و شکل برای پوسته و اجزای مهم هستند. این روش، تغییر مرحله‌ای و قابل بازبینی را ممکن می‌کند، بی‌آنکه در این مرحله بازنویسی پرریسک تمام component CSS انجام شود.

### ۲. پالت رنگ

| نقش | مقدار | کاربرد |
|---|---|---|
| Canvas | `#F7F9F7` | زمینهٔ صفحه و transcript |
| Surface | `#FFFFFF` | ورودی، کارت و کنترل |
| Surface soft | `#F2F5F2` | زمینهٔ ملایم برای حالت ثانویه |
| Ink | `#1E2822` | عنوان و متن اصلی |
| Body text | `#39463F` | بدنهٔ پیام‌ها |
| Muted | `#596960` | متن ثانویه و فراداده |
| Border | `#DFE6E1` | تفکیک کم‌تأکید |
| Border strong | `#C7D2CA` | مرز فیلدها و کنترل‌ها |
| Primary | `#176448` | ارسال، اقدام اصلی و قیمت قابل‌خواندن |
| Primary soft | `#EAF4EE` | انتخاب‌شده/موفق بدون سطح اشباع |
| Danger | `#A2342B` | خطا و بازیابی |
| Warning | `#785116` | هشدار و وضعیت نامشخص |
| Info | `#265B8F` | اطلاعات خنثی، فقط در موارد نیاز |

پالت به‌عمد سبز تیره را فقط برای موارد مهم استفاده می‌کند. سطح‌های سبز، کارت‌ها و متن ثانویه را سبز نمی‌کنیم؛ این کار از یکنواختی و رقابت رنگی جلوگیری می‌کند. خطا و هشدار نیز فقط با تغییر رنگ نشان داده نمی‌شوند و باید متن وضعیت را داشته باشند.

### ۳. بررسی کنتراست نمونه‌های اصلی

محاسبهٔ نسبت کنتراست با فرمول نسبی luminance در WCAG انجام شد. مقادیر زیر برای جفت‌رنگ مشخص‌شده‌اند، نه به‌عنوان ادعای تأیید همهٔ پیکسل‌های برنامه:

| متن/پیش‌زمینه | پس‌زمینه | کنتراست |
|---|---|---:|
| `#1E2822` | `#F7F9F7` | 14.36:1 |
| `#39463F` | `#F7F9F7` | 9.35:1 |
| `#596960` | `#F7F9F7` | 5.49:1 |
| `#176448` | `#FFFFFF` | 7.11:1 |
| `#FFFFFF` | `#176448` | 7.11:1 |
| `#A2342B` | `#FFF2F0` | 6.27:1 |
| `#785116` | `#FFF8E8` | 6.64:1 |
| `#265B8F` | `#EFF6FF` | 6.49:1 |
| `#26332B` | `#EEF2EF` | 11.68:1 |

این مقادیر برای متن معمولی از معیار AA متنی 4.5:1 بیشتر هستند؛ وضعیت نهایی باید در مرورگر هم بررسی شود، چون ممکن است قواعد legacy خارج از این رنگ‌های اصلی همچنان وجود داشته باشند.

### ۴. فونت و تایپوگرافی فارسی

اولویت فونت به این صورت است:

`Vazirmatn → IRANYekanX → IRANSansX → Segoe UI → Tahoma → Arial → sans-serif`

وزیرمتن از منبع رسمی پروژهٔ فونت به‌صورت stylesheet CDN با نسخهٔ ثابت معرفی شده است. منبع خارجی یک وابستگی اختیاری است: در صورت عدم دسترسی، fallbackهای نصب‌شدهٔ سیستم استفاده می‌شوند؛ بنابراین لود نشدن فونت نباید UI را از کار بیندازد.

مقیاس مورد استفاده بر نقش استوار است، نه اندازه‌های تصادفی:

| نقش | اندازهٔ هدف | وزن | خط |
|---|---:|---:|---:|
| متن پیام و فرم | 15px دسکتاپ / 14px موبایل | 400 | حدود 1.85–1.9 |
| برچسب و فراداده | 12–13px | 400–500 | 1.6–1.75 |
| عنوان کارت/فرم | 14–16px | 600–700 | 1.5–1.7 |
| قیمت اصلی | 16–17px | 700 | 1.6 |
| عنوان حالت شروع | 24px دسکتاپ / 22px موبایل | 700 | 1.5 |

از وزن 750/800/850 برای هر جزء استفاده نمی‌شود؛ این وزن‌های زیاد در CSS قبلی باعث می‌شدند همه‌چیز تقریباً bold دیده شود. فاصله‌گذاری حروف برای فارسی صفر نگه داشته شده است تا اتصال حروف آسیب نبیند.

### ۵. چیدمان و hierarchy

- پوستهٔ تمام‌قد چت و transcript مستقل همچنان حفظ می‌شود.
- header سبک است و فقط برند، محل داده و وضعیت اتصال را نشان می‌دهد.
- پیام کاربر با زمینهٔ خنثی جدا می‌شود؛ متن دستیار زمینهٔ بزرگ و اضافی نمی‌گیرد.
- قیمت مهم‌ترین مقدار در کارت محصول است، نام محصول پس از آن می‌آید، و فروشگاه/نشانی/تازگی قیمت در سطح ثانویه اما خوانا قرار دارند.
- بازکردن فروشگاه‌ها اقدام اصلی مرحلهٔ بعد است؛ مقایسهٔ مدل، اقدام ثانویه.
- فرم Generative UI، گزینه‌های انتخاب و جدول مقایسه یک زبان بصری مشترک دارند.
- composer کادر مشخص و دکمهٔ ارسال برجسته دارد، ولی shadow و border آن ملایم است.
- خطا، هشدار، موفقیت و وضعیت در حال پردازش با متن و رنگ معنایی متفاوت دیده می‌شوند.

   https://developers.openai.com/plugins/concepts/ui-guidelines
2. **OpenAI Apps SDK UI (repository)** — توکن‌های طراحی، spacing، رنگ، تایپوگرافی و اجزای قابل دسترس به‌عنوان معماری سیستم طراحی استفاده می‌شوند.
   https://github.com/openai/apps-sdk-ui
3. **OpenAI Shopping Research** — کشف محصول به شکل مکالمه‌ای، پرسش تکمیلی، نتایج بصری و مقایسهٔ چند گزینه را پشتیبانی می‌کند.
   https://help.openai.com/en/articles/12911370-using-shopping-research-in-chatgpt
4. **Microsoft Fluent 2 Typography** — hierarchy روشن، type ramp دارای نقش و کنتراست خوانا برای متن.
   https://fluent2.microsoft.design/typography
5. **Microsoft Fluent 2 Accessibility** — کنتراست متن و اجزای تعاملی، فوکوس و بازچینی واکنش‌گرا.
   https://fluent2.microsoft.design/accessibility
6. **WCAG 2.2** — معیارهای دسترس‌پذیری مستقل از تکنولوژی و هدف تعاملی.
   https://www.w3.org/TR/WCAG22/
7. **Vazirmatn project** — فونت فارسی/عربی، stylesheet نسخه‌دار CDN و مجوز فونت.
   https://github.com/rastikerdar/vazirmatn
8. **OpenAI Frontend prompting guidance** — تجربهٔ کاربردی و دامنه‌محور به‌جای hero/کارت‌های تزئینی؛ استفاده از سلسله‌مراتب، توکن‌ها و کنترل‌های متناسب.
   https://developers.openai.com/api/docs/guides/frontend-prompt

## معیارهای بررسی بعد از اعمال

- [ ] صفحه در عرض‌های 320، 390، 768 و 1440px با RTL درست باقی بماند.
- [ ] composer در عرض کم به بیرون viewport نرود و ارسال همچنان قابل دسترس باشد.
- [ ] عنوان و قیمت کارت در نگاه اول قابل تشخیص باشند؛ metadata با متن 12px یا بیشتر خوانا بماند.
- [ ] همهٔ دکمه‌ها دارای hover، focus-visible، disabled و loading قابل تشخیص باشند.
- [ ] فرم رادیویی/checkbox وضعیت انتخاب‌شده را علاوه بر رنگ نشان دهد.
- [ ] اطلاعات قیمت ثبت‌شده از تأیید موجودی تفکیک شود.
- [ ] فونت وزیرمتن در Network اگر در دسترس است با وضعیت 200 بارگیری شود؛ اگر نه fallback متنی بدون layout break عمل کند.
- [ ] `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` و سپس `docker compose build --no-cache frontend` روی میزبان اجرا شوند.

## محدودیت اعتبارسنجی

رنگ‌های توکن و نسبت‌های کنتراستشان محاسبه شده‌اند و CSS با parser مستقل از نظر syntax بررسی می‌شود. در این محیط، مرورگر محلی پروژه و npm install کامل روی میزبان کاربر در دسترس نیست؛ بنابراین این فایل ادعای آزمون بصری واقعی یا تکمیل build محیط کاربر را مطرح نمی‌کند.
