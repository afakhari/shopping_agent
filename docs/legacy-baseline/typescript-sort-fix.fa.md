# اصلاح خطاهای TypeScript مربوط به `CatalogSort`

## علت

`MissionConstraints.sort` مقدار `distance_asc` را می‌پذیرد، اما نوع `CatalogSort` در API جست‌وجوی کاتالوگ فقط این مقادیر را مجاز می‌داند: `relevance`، `price_asc` و `recent_price_change`. علاوه بر این، endpoint جست‌وجوی رابط فعلی مختصات مبدأ ارسال نمی‌کند؛ بنابراین مرتب‌سازی فاصله در این صفحه قابل اجرا نیست.

## اصلاح

در `frontend/src/app/App.tsx` دو مورد تغییر کرده است:

1. تابع `isCatalogSort` مقادیر مجاز برای جست‌وجوی کاتالوگ را بررسی می‌کند.
2. تابع `toCatalogSort` مقدار ذخیره‌شده یا بازیابی‌شده را به نوع سازگار تبدیل می‌کند و مقادیر نامعتبر/پشتیبانی‌نشده مانند `distance_asc` را فعلاً به `relevance` برمی‌گرداند.

این اصلاح هر دو خطای گزارش‌شده را برطرف می‌کند، بدون اینکه `distance_asc` را به API بفرستد که به مختصات مبدأ نیاز دارد. وقتی UI انتخاب مبدأ و ارسال `lat`/`lon` پیاده‌سازی شد، می‌توان پشتیبانی از `distance_asc` را به‌صورت end-to-end اضافه کرد.

## اعمال روی Windows

ZIP را در ریشه `D:\projs\bazaar-compass` استخراج کنید و فایل موجود را جایگزین کنید؛ ساختار ZIP از ریشه پروژه آغاز می‌شود. سپس اجرا کنید:

```powershell
Set-Location "D:\projs\bazaar-compass\frontend"
npm run typecheck
npm run lint
npm run build
```

در محیط ساخت این بسته، وابستگی‌های runtime فرانت‌اند نصب نیستند؛ بنابراین نتیجه اجرای کامل TypeScript در اینجا تأیید نشده است. خروجی کاربر پیش از اصلاح، نشان می‌داد که دو خطای مشخص در App.tsx وجود دارد؛ این patch دقیقا همان ناسازگاری نوع را اصلاح می‌کند.
